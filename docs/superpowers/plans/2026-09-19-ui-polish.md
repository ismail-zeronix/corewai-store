# CoreWAI Supply UI Polish Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Apply the approved "clean premium minimal" visual system (shadow scale, radius convention, desaturated badges, decluttered header/hero) consistently across the CoreWAI Supply storefront without changing brand colors or fonts.

**Architecture:** Introduce two new shadow design tokens and a fixed radius convention at the CSS-variable level, propagate them through the shared `Card` primitive and `ProductCard` (which every product grid on the site already reuses), then apply the same discipline directly to the header, hero, and the handful of PLP/cart/checkout controls that still use the old radius convention.

**Tech Stack:** Next.js 16, Tailwind CSS v4 (`@theme` tokens), React 19, `class-variance-authority`, `cn` (from the `cn` package), `lucide-react` icons.

**Spec:** `docs/superpowers/specs/2026-09-19-ui-polish-design.md`

## Global Constraints

- No changes to brand color values in `:root` (`--brand-blue`, `--brand-cyan`, `--brand-cyanink`, `--brand-lime`, `--brand-ink`, `--brand-cloud`, `--brand-mist`, `--brand-error`, `--brand-amber`, `--brand-amberink`, `--brand-green`, `--brand-greenink`).
- No font changes — keep the Inter (`--font-display`) / Manrope (`--font-body`) pairing from `frontend/src/app/layout.tsx`.
- No new pages, routes, or backend/API changes.
- Radius convention (apply consistently, do not invent per-component variants): `rounded-xl` for cards/inputs/standard containers, `rounded-2xl` for hero/media blocks, `rounded-full` for pills/avatars/badges only.
- This repo has no automated UI test suite. Per the spec's testing plan, "tests" in this plan mean: TypeScript compiles, `npm run lint` passes, `npm run build` succeeds, and a manual visual check of the affected page(s) in the dev server. Every task's verification step follows this pattern instead of `pytest`/`jest`-style unit tests.
- All file paths below are relative to `frontend/` unless stated otherwise.
- Preserve all existing `aria-*`, `focus-visible:*`, and `min-h-11`/`size-11` touch-target attributes exactly as they appear today — this is a visual pass, not an accessibility refactor.
